# Scopes

API key scopes control which operations a key can perform. Scopes are assigned when creating an API key and determine whether the key can read, write, or delete checks, and whether it can see or change alert channels.

## Available Scopes

| Scope | Description |
|---|---|
| `checks:read` | List checks, get check details, history, and stats |
| `checks:write` | Create, update, and toggle checks |
| `checks:delete` | Delete checks |
| `alerts:read` | See which email addresses and webhooks receive alerts |
| `alerts:write` | Change email alert settings, add or delete webhooks, and send test alerts |

The alert scopes are separate from the check scopes: a `checks:write` key can't add a webhook. Keys created before the alert scopes existed have neither.

## Default Scope

API keys created without specifying scopes default to **`checks:read`** only. This means existing keys are read-only and cannot modify your checks.

## Scope Requirements by Endpoint

| Endpoint | Method | Required Scope |
|---|---|---|
| `/v1/public/checks` | GET | `checks:read` |
| `/v1/public/checks/status` | GET | `checks:read` |
| `/v1/public/checks/{id}` | GET | `checks:read` |
| `/v1/public/checks/{id}/history` | GET | `checks:read` |
| `/v1/public/checks/{id}/stats` | GET | `checks:read` |
| `/v1/public/checks` | POST | `checks:write` |
| `/v1/public/checks/{id}` | PATCH | `checks:write` |
| `/v1/public/checks/{id}/toggle` | POST | `checks:write` |
| `/v1/public/checks/{id}` | DELETE | `checks:delete` |
| `/v1/public/account` | GET | `checks:read` |
| `/v1/public/alerts/email` | GET | `alerts:read` |
| `/v1/public/alerts/email` | PATCH | `alerts:write` |
| `/v1/public/alerts/email/test` | POST | `alerts:write` |
| `/v1/public/alerts/webhooks` | GET | `alerts:read` |
| `/v1/public/alerts/webhooks` | POST | `alerts:write` |
| `/v1/public/alerts/webhooks/{id}/test` | POST | `alerts:write` |
| `/v1/public/alerts/webhooks/{id}` | DELETE | `alerts:write` |

## Error Response

If your API key does not have the required scope, the API returns a `403 Forbidden`:

```json
{
  "error": "Credential does not have the required scope: checks:write"
}
```

## Restricting a Key to Checks or Folders

Scopes control *what* a key may do. To also limit *which checks* it may do it
to, restrict the key to specific checks and/or folders when you create it. A
folder includes its subfolders. Checks outside the grant return `404`, and a
restricted key can only create checks inside an allowed folder. See
[Authentication](/api-reference/authentication#restricting-a-key-to-checks-or-folders)
for the full rules.

## Creating a Scoped Key

When creating an API key in **Settings > API**, select the scopes you need. You can assign multiple scopes to a single key.

For full access to checks, enable `checks:read`, `checks:write`, and `checks:delete`. Add `alerts:read` and `alerts:write` to manage alert channels too.
